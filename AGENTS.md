# AGENTS.md — Autonomous FPGA/ASIC Design Agent

## Project Overview

This is a full-stack system for an **autonomous AI agent** that writes, simulates, and synthesizes Hardware Description Language (HDL, i.e. Verilog) for FPGAs and ASICs. The user chats with the agent from a web UI; the agent calls EDA tools to synthesize designs and reports PPA (Power, Performance, Area) results.

- **Model providers**: project-selectable OpenAI-compatible models resolved through `backend/model_registry.py`. Supported choices are direct Kimi K3 (`KIMI_API_KEY`), Kimi K2.7 Code through OpenRouter (`OPENROUTER_API_KEY`), and Kimi K3 through OpenRouter (`OPENROUTER_API_KEY`). Direct Kimi is only the legacy default when a project has no explicit model; it is not required when an OpenRouter model is selected. Direct-Kimi overrides remain `KIMI_MODEL` and `KIMI_BASE_URL`.
- **Agent framework**: none — `backend/agent_core.py` implements the tool-calling loop directly with the `openai` Python client
- **Backend**: FastAPI (Python), WebSocket-based chat
- **Frontend**: React 19 + Vite 8 + Tailwind CSS 4 + shadcn/ui (plain JavaScript, no TypeScript)
- **EDA toolchain**: SiliconCompiler (Yosys, Verilator, OpenROAD); storage locations come from env vars `SCPATH` / `SC_BUILDS` (see `backend/eda_tools.py`), set to `/mnt/cold-hdd` paths in `backend/.env` on this machine

### Backend modules (`backend/`)
### Optimization controller (Phases 1–4)

Phase 1 maintains exact simulation-passing RTL checkpoints, a measured best revision, deterministic comparison, and bounded retries with a one-run optimization cap. Phase 2 builds bounded model context with token admission checks. Phase 3 makes progress visible through structured planning/tool/timing/revision events, attempt counts, token/tool/context budgets, metric deltas, and explicit rejection/restoration reasons; detailed tool output remains collapsed in the UI. Phase 4 stages candidate optimization with cheap synthesis + STA, an exact promotion token bound to the candidate and constraints, and at most one full P&R run for the promoted candidate in an isolated build path. The promotion (token + binding + comparison baseline) is serialized with the persisted candidate lineage and restored on load, so a backend restart keeps the one allowed full-P&R experiment available; a full-P&R request that carries a VALID token but a different (regenerated, never-simulated) RTL is rejected with `FULL PNR SOURCE MISMATCH` naming the promoted checkpoint's artifact handle instead of the generic simulation-checkpoint message, and the promotion notice itself tells the model to pass the promoted source handle — never regenerate the RTL. A full-P&R request carrying a token with no pending matching promotion and an unverified source gets `FULL PNR TOKEN UNKNOWN` with the complete re-earn path (re-screen on the sim-passed artifact, fresh token, then full-pnr). Both corrective gates (`TOKEN UNKNOWN`, `SOURCE MISMATCH`) return plain tool results, never `_stop_message` — a terminal stop killed the run before the model could act on the instruction (field failure: the model hallucinated a token, got the re-earn instruction, and the run died anyway because `run_stop_reason` was set). On load, `last_good_verilog` is also seeded from the durable SIMULATION PASSED transcript (`_durable_sim_checkpoint`) when the persisted lineage has no active member — staged screens never became the active checkpoint, which used to leave CURRENT ARTIFACTS offering a later unverified rewrite after a restart. Validation with the fixed `matmul3` regression and its 50 MHz closure report is pending; these remain engineering comparisons and evidence and stop short of signoff.


- `main.py` — FastAPI app (lifespan starts/stops the JobManager). `GET /health` health check (also reports `model`, `api_key_set`, `models_available` — the count of registry entries whose API key is set — and `models_healthy` — the count whose cached probe status is `ok`); `WebSocket /ws` chat endpoint. Incoming plain-text messages are passed to `agent_core.chat()` (an async generator) **in a per-message task** (chats serialized **per session** by the `_SESSIONS` map (`_SessionChat`: lock + bounded event buffer + subscriber queues + `chat_task` — the running chat task handle, recorded by `start_chat` on the session it runs under and cleared by the task's done-callback): a second message for the same session while a chat is running — including a detached one after disconnect, which still holds the lock — is rejected immediately with an error frame "Agent is already working on this project…" + `end`; different sessions run concurrently. Chat frames are published to the **session's event buffer** (deque of (seq, event), maxlen 1000, cleared at the start of each run; `emit()` stamps every chat frame with a wall-clock `ts` used for the console's discreet per-row timestamps — it survives the buffer replay after a page refresh) instead of the originating connection; each connection bound to a session holds a `_ChatSub` (its loop + outbox + a `skip_upto` cursor) and `emit()` delivers via `loop.call_soon_threadsafe(outbox.put_nowait, …)` — thread-safe even if the chat task and the connection run on different loops (TestClient runs one portal per websocket; production is single-loop uvicorn). Multiple clients on the same project all watch the run, and a client that (re)joins mid-run gets a `{"type":"busy"}` frame plus an inline replay of the buffer snapshot (events with seq ≤ the new sub's `skip_upto`, so no duplicates), then live events. Job/subscription frames keep flowing through the per-connection outbox directly — the two paths meet in the outbox queue without a shared ordering guarantee (job logs carry their own seq cursors)); ALL outbound frames go through a single per-connection outbox queue with one sender task, so the receive loop stays responsive during a chat — this is what lets a client subscribe to a job's log *while* the tool call that owns it is still running. Chat events include legacy `text`, `tool_call`, `tool_result`, and `error` frames plus `generation_start`, `text_delta`, provider-exposed `reasoning_delta`, `generation_usage`, and `generation_end`; each run terminates with `{"type":"end"}`. On client disconnect an in-flight chat task is deliberately NOT cancelled — it finishes server-side (its events just accumulate in the dead connection's outbox; history persists as usual when it ends) and is held in the module-level `_DETACHED_CHATS` set because asyncio only weak-references tasks (a task referenced only by the dead endpoint frame would be GC-cancelled mid-run). A `{"type":"cancel"}` frame cancels the chat task of the session the connection is **currently bound to** (looked up on `_SessionChat.chat_task`, via `task.get_loop().call_soon_threadsafe(task.cancel)` since the task may live on another connection's loop) — so the stop button works after a page refresh and from any client watching the project; the cancelled run emits "Run cancelled by user." into the session buffer, reaching every bound client. `tool_call` content is JSON `{"name", "args"}`. Each connection gets a uuid session id with its own chat history; sending `{"project": "proj-…"}` switches the session and replays the persisted history as a `{"type": "history", "content": [...]}` frame, followed by a `{"type": "project_state", "verilog"?, "metrics"?, "lint"?}` frame when the project JSON carries persisted dashboard state (`lint` = the last `write_and_check_syntax` verdict digest-bound to the dashboard RTL — `bound: false` means the verdict belongs to an older revision; keys omitted when absent; old clients ignore the unknown frame type), plus the mid-run `busy`+replay sequence described above. CORS is wide open (`allow_origins=["*"]`) for local dev. Project management REST endpoints (persisted under `backend/projects/<id>.json` via `agent_core`): `GET`/`POST /api/projects` (POST accepts an optional `{"model": "<registry key>"}` — 422 on unknown key), `PATCH /api/projects/{id}` (rename and/or model change and/or reasoning-effort change: optional `name` — non-empty after stripping, ≤120 chars — optional `model`, and optional `reasoning_effort` (UNSET sentinel: absent = unchanged, null = clear to the registry default, string = must be accepted by the project's model; a model change drops a stored effort the new model does not support); 422 on empty/oversized name, unknown model key, or unsupported effort, 404 for unknown id), `DELETE /api/projects/{id}`. `GET /api/models` returns the model registry entries (`key`, `display_name`, `available`, `default`, `health` — awaited from the TTL cache, so it's fast after the first probe round — plus the effort capabilities `reasoning_efforts` and `reasoning_effort_default` for the per-project effort selector) for the frontend dropdown. Mistral setup wizard REST surface (see `mistral_setup.py`): `GET /api/providers/mistral/setup/state`, `POST .../browser/start`, `GET .../browser/status`, `POST .../browser/complete`, `POST .../key` — the browser-flow exchanges happen server-side and the API key is never returned to the client. `GET /api/jobs` lists recent EDA jobs (id, kind, status, design, created_at, finished_at, session) from the jobs DB — the build registry. The `/ws` endpoint also accepts job-control frames: `{"type":"subscribe","job_id":"…","since_seq":N}` (replays ring entries with seq > since_seq, then streams live; runs as its own task per subscription) and `{"type":"cancel_job","job_id":"…"}`; every chat websocket is registered as a JobManager listener (via the outbox adapter) and receives `{"type":"job_started","job_id","kind","design","session"}` broadcasts the moment a tool submits a job (this is how the frontend learns the job_id early enough to watch the log live — the `job_id:` marker in the tool_result only arrives when the job finishes).
- `jobs.py` — **JobManager (Task 4)**: in-process asyncio job registry decoupling EDA work from the WebSocket lifecycle. `submit(kind, params, *, runner, design=None, session=None)` starts a job as its own asyncio task (`runner` is `async def runner(job) -> str`, the result string delivered to `job.wait()` callers); *session* tags the job with the owning chat session (project id) — stored in the nullable `session` TEXT column (startup migration: `PRAGMA table_info` + `ALTER TABLE ADD COLUMN` for DBs created before it), returned by `GET /api/jobs` and carried in the `job_started` broadcast, so the frontend can filter the global registry per project; `cancel(job_id)` cancels the task — the `CancelledError` path SIGTERMs the subprocess **process group** (`start_new_session=True`, pgid == child pid) and escalates to SIGKILL after 10 s; `subscribe(job_id, ws, since_seq=0)` replays then streams; for DB-only jobs (previous backend run, ring gone) it replays the surviving disk log (seq = line number) before shipping the final status. Job states: queued|running|done|failed|cancelled|interrupted. Each job has a ring buffer `deque(maxlen=2000)` of `(seq, line)`, a set of subscriber queues (bounded at 500 — drop-oldest + `log_gap` marker on overflow, so a slow client never blocks the log reader), and a disk log at `backend/data/jobs/<job_id>/job.log`. Persistence: SQLite via aiosqlite at `backend/data/jobs.db` (schema in `jobs.py`; NOT under SC_BUILDS; `data/` is gitignored). Startup reconciliation (lifespan): rows still `running`/`queued` whose recorded pgid is gone (`os.kill(pgid, 0)`) become `interrupted`. Server→client frames: `tool_log` (`job_id`,`seq`,`line`), `job_status` (`job_id`,`status`,`manifest` — manifest carries the PPA metrics dict on `done`), `log_gap` (`job_id`,`from_seq`), plus the `job_started` broadcast above. Subprocesses are always spawned with `asyncio.create_subprocess_exec(..., stdout=PIPE, stderr=STDOUT, start_new_session=True, env={**os.environ, "PYTHONUNBUFFERED": "1"})`, read line-by-line, and always reaped with `await proc.wait()`; never use blocking `subprocess.run` in the job path. Note: aiosqlite's worker thread is not a daemon — always `await manager.stop()` (tests use try/finally) or the process will not exit.
- `agent_core.py` — LLM integration via `model_registry`: OpenAI function-tool schemas, a tool-calling loop (max 10 rounds), per-session message history. The `AsyncOpenAI` client and provider model id are resolved **per session** by `_client_for(session_id)` from the session's registry key (`_session_model_key`): project sessions use the project JSON's optional `"model"` field (absent → registry default, so legacy projects behave exactly as before), non-project sessions always use the default. Clients are built with an explicit `timeout=httpx.Timeout(LLM_TIMEOUT_S=900, connect=10)` + `max_retries=2` — the SDK default (600 s/attempt) let a stalled completion hang a chat silently; 900 s because a legitimate K3 first-round generation for a large design was measured at ~9 min (540 s), so 300 s killed real runs. Completions now stream end-to-end with live text/provider-exposed reasoning deltas, fragmented tool-call assembly, usage frames, and separate first-token, inactivity, and overall deadlines. Reasoning is read from `reasoning_content`/`reasoning` delta fields (Kimi style) and, for Mistral reasoning models such as `zai-glm-5-3`, unpacked from the typed content chunks Mistral streams inside `delta.content` (`_typed_content_chunk_items`: ThinkChunk `{"type":"thinking","thinking":[{"type":"text",…}]}` → `reasoning_delta`, TextChunk → `text_delta` — Mistral deviates from the OpenAI wire format here; without the unpacking the chunks are dropped and the run dies on the first-token timeout while the model thinks). Per-request `max_tokens` is sized per model: reasoning models get `REASONING_OUTPUT_TOKEN_LIMIT` (default 65k) because thinking shares the completion budget — a plain-model 32k cap made GLM 5.3 stop with `finish_reason=length` and an empty response. That empty-length stop still triggers the single bounded continuation (`MAX_EMPTY_CONTINUATIONS`), and when the registry entry declares effort levels the retry request also sends `reasoning_effort: "low"` via `extra_body` (`_continuation_request_kwargs`), because an identical retry would burn the same budget on thinking again; a second empty length stop surfaces the honest empty-response error. A missing API-key env var yields an `{"type": "error"}` frame in chat instead of raising. Tool functions that return an awaitable (the job-backed ones in `eda_tools.py`) are awaited. Around each tool invocation the session id is published via the `eda_tools.current_session` contextvar (set/reset per call) so `JobManager.submit` can tag jobs with the owning project. While awaiting each chat completion (wrapped in a task + shielded `asyncio.wait_for`), a status event is emitted immediately and then every `STATUS_HEARTBEAT_S` (15 s; monkeypatched in tests): `{"type":"status","content":"Waiting for model response… 3:15 elapsed (round 2)"}` — the blind spot between prompt and first frame (K3 first rounds measured at 9-10 min) made thinking indistinguishable from hung; on chat cancel the in-flight completion task is cancelled with the chat. The system prompt (SYSTEM_INSTRUCTION) includes sky130 frequency guidance (conservative 40–66 MHz, never below 8 ns) and timing-closure guidance: pipeline long combinational datapaths by default at ≥50 MHz, fix setup violations by splitting the longest combinational chain with a pipeline register (then re-verify and re-measure), and never claim timing closure without a measured slack from `run_silicon_compiler`/`find_fmax`. Also owns project persistence (`proj-*` sessions saved to `backend/projects/<id>.json`): `list_projects`, `create_project(name, model=None)` (validates the registry key, KeyError on unknown), `update_project(name=None, model=None)` (rename and/or model change; `rename_project` delegates to it), `delete_project`. Project JSON also stores `created` (first-save timestamp; `list_projects` entries carry `created` + `updated` — file mtime, i.e. last activity — for the frontend sort controls). `_save_project` additionally persists dashboard state derived from the history by `_derive_latest_state` (assistant history entries carry full tool_call arguments): `latest_verilog: {top, code}` (last tool call with `verilog_code`) and `latest_metrics` (metric lines re-parsed from tool-result text, same patterns as the frontend's `extractMetrics`); `get_project_state(session_id)` reads them back for the `project_state` frame. **Repair policy (Task 5)**: per-session in-memory state (`_session_state`, cleared by `reset_session`/`delete_project`) tracks failed syntax checks (cap `SYNTAX_REPAIR_CAP` = 5), failed tool attempts overall (cap `TOTAL_REPAIR_CAP` = 10), the last sim-passing Verilog snapshot, and accumulated token usage. `_postprocess_tool_result()` enforces the budgets in the tool loop: when a cap is hit it appends a "BUDGET EXHAUSTED — change strategy" notice to the tool result (syntax cap also appends a unified diff of the last vs. current lint attempt; the total cap points at the last sim-passing code for restore). A passing simulation resets the syntax counter. Every tool result also ends with a token line: `tokens_remaining: N` if the API reports a remaining budget, otherwise honest session-accumulated `tokens_used (this session): N`.

Entries: `"kimi-k3"` (`DEFAULT_MODEL_KEY`; base_url from `KIMI_BASE_URL` else the Kimi Code endpoint, model_id from `KIMI_MODEL` else `k3` — both env overrides read at call time; health probe `GET {base_url}/models`), `"mistral-vibe"` (Mistral platform API following Mistral Vibe's own connection flow — upstream `mistralai/mistral-vibe` `vibe/core/config/_defaults.py`/`schema.py`: key from `MISTRAL_API_KEY`, base_url `https://api.mistral.ai/v1` overridable via `MISTRAL_BASE_URL`, model_id `mistral-medium-3-5` (Vibe's default `active_model`) overridable via `MISTRAL_MODEL`; health probe `GET /v1/models`, verified live to 401 without a valid key), `"mistral-glm-5.3"` (GLM 5.3 hosted by Mistral — model id `zai-glm-5-3` per docs.mistral.ai, same `MISTRAL_API_KEY` platform API and the same free `GET /v1/models` probe; a reasoning model that always streams typed thinking/text chunks inside `delta.content` — parsed by `_typed_content_chunk_items` in `agent_core.py` — and rejects `reasoning_effort: none`), `"openrouter-kimi-k2.7-code"` and `"openrouter-kimi-k3"` (base_url `https://openrouter.ai/api/v1`, key from `OPENROUTER_API_KEY`, model ids `moonshotai/kimi-k2.7-code` / `moonshotai/kimi-k3` as listed in the OpenRouter catalog; health probe `GET /auth/key` — a free credit-metadata endpoint). Helpers: `get_model(key)` (KeyError on unknown), `list_models()` → `[{key, display_name, available, default}]` where `available` means the entry's api-key env var is set, and async `verify_model(key)` / `verify_all()` — proactive, FREE key verification (an authenticated GET only; no completion call is ever issued; both probe endpoints return 401 without a valid key — checked live) returning `ok | auth_failed | unreachable | unknown | no_key` (404 on the probe path → `unknown`, i.e. unverifiable for free). Probe results are cached in memory for `HEALTH_TTL_S` (60 s, `no_key` is never cached), timeout 5 s, via `httpx` (already a dependency); keys and response bodies never appear in output.

- `mistral_setup.py` — **Interactive Mistral setup wizard** (browser sign-in + paste-key), a faithful port of `vibe --setup` from upstream `mistralai/mistral-vibe` (`sign_in_flow.rs`/`sign_in_gateway.rs`): PKCE S256 code_verifier/challenge, `POST {console}/api/vibe/sign-in` → authenticate URL at `console.mistral.ai/codestral/cli/authenticate?…`, 3 s polling (`410` = expired, statuses `pending|completed|expired|denied|error`), `POST …/{process_id}/exchange` for the API key, tenant `whoami` domains reported after the exchange; custom login domains follow Vibe's "Other" step (bare domain entered, auth API base derived as `DOMAIN/api`, URL validation checks origin + path prefix). `verify_api_key()` re-validates the exchanged key with the free `GET /v1/models` probe before saving; `save_api_key_to_env()` writes `MISTRAL_API_KEY` into `backend/.env` (mkdir parent, never overwrites without `force`, atomic temp+rename), mirrors it into the durable store `backend/data/provider_keys.env` (that directory is bind-mounted in docker-compose, so the key survives `docker compose down/up` — the image-layer `.env` does not), and exports it into `os.environ` so the running backend adopts it **without a restart** (the registry reads the env at call time). `load_provider_keys()` is called by `main.py` at startup right after the `.env` loads, with setdefault semantics so a hand-written `.env` keeps precedence. - `eda_tools.py` — Agent tools: `run_simulation(verilog_code, testbench_code, top_module)` runs a self-checking testbench with iverilog or verilator (verification before synthesis); `run_silicon_compiler(verilog_code, top_module, target="skywater130_demo", clock_period_ns=None)` synthesizes Verilog (SiliconCompiler 0.38+ `ASIC`/`Design` API) and returns PPA metrics read from the result manifest `<build>/<top>/job0/<top>.pkg.json` (path `metric/<name>/node/<step>/0/value`); it auto-selects the deepest flow the installed EDA executables support (full ASIC P&R if openroad+klayout, synthesis+STA if yosys+`sta` — note OpenSTA's binary name, synthesis-only if only yosys). When `clock_period_ns` is given, `_write_sdc()` generates `<top>.sdc` with `create_clock` on the auto-detected clock port, `set_clock_uncertainty`, 20% I/O delays on `[all_inputs]`/`[all_outputs]`, a sky130 input buffer driving cell when the target is skywater130-based, `set_load 0.03`, and a `set_false_path` for any detected async reset. The SDC is added as an `sdc` fileset (same pattern as `siliconcompiler.demos.asic_demo`), which is how the demo targets pick up constraints — without it every run logs "No clocks defined" and slack metrics are null. **If `clock_period_ns` is omitted but the RTL declares a `clk` input, a 10 ns default is applied automatically** so sequential designs are never accidentally unconstrained. Default target is skywater130_demo because freepdk45_demo's `route.antenna_repair` input wiring is broken with the installed SC 0.38 / OpenROAD 26Q2 combo. `find_fmax(verilog_code, top_module, target="skywater130_demo")` runs a bounded coarse-to-fine synthesis+STA search over a configurable period bracket. It probes the endpoints and midpoint, refines the feasible/infeasible boundary to the requested tolerance within a hard run budget, confirms the selected feasible point, rejects non-monotonic evidence, and reports period/frequency bounds, uncertainty, constraints, toolchain, assumptions, and every observation. The per-design build lock is held across the whole search. `write_and_check_syntax(...)` does a real lint with the first available of slang/verilator/iverilog/yosys (fast, stays synchronous — a lint is a single sub-second subprocess, so it doesn't need a job) and returns a **structured JSON diagnostic report** (see `lint.py`). **The long-running tools are async and execute as JobManager jobs** (kinds `simulation`/`synthesis`/`fmax`, see `jobs.py`; each `submit` passes `session=current_session.get()` — a module-level contextvar set by `agent_core` around tool invocation — so jobs are tagged with the owning project), and `run_silicon_compiler`/`find_fmax` are additionally serialized **per design** by `_build_lock(top_module)` — concurrent builds of the same top share the SC build dir and would stomp each other's node dirs, so a second call for a design already building fails fast ("another build for design X is already running (job_id …)"); different designs build in parallel. Locks are loop-bound and rebind like `JobManager._ensure_started`.: `run_simulation` runs the compile + simulate steps via `job.run_process(...)`; `run_silicon_compiler` and `find_fmax` run SC in a dedicated subprocess — `sc_job.py`, a standalone CLI runner that rebuilds the project, runs the flow, streams SC's console to stdout (which IS the job's live log, via `job.run_process`), and prints a final `SCJOB {...}` machine line. NEVER run `project.run()` in a worker thread of the backend: SC's scheduler forks node processes, and forking a multithreaded asyncio process makes the children exit non-zero at shutdown — nodes get recorded as 'error' despite clean logs (field fix #4). Cancel is a plain process-group kill. On failure the tool result now includes the last ~2.5 KB of SC output so the agent sees the real node error. The agent-visible result text is unchanged from the pre-JobManager format except a final marker line `job_id: <id>` (parsed by the frontend; the agent can ignore it). Storage paths are read from the environment at call time: `SCPATH` (SC cache; default `~/.local/share/asic-agent` — deliberately not `~/.sc`, which belongs to SC itself) and `SC_BUILDS` (build outputs `<build>/<top_module>/`; default `./build`). On this machine both point at `/mnt/cold-hdd` via `backend/.env` (template: `backend/.env.example`).
- `lint.py` — **Structured lint diagnostics (Task 5)**. One parser per linter converts native output to normalized dicts (`file/line/col/code/severity/msg`), and `build_result()` produces the agent-facing schema: `{"tool", "tool_version", "ok", "verdict", "code_sha256", "saved_to", "errors": [...], "errors_total", "warnings_total", "truncated", "raw_stderr_tail"}`. `verdict` is `ok | lint_warning | syntax_error | elaboration_error`; `ok` is true for `ok` and `lint_warning` (warnings don't block simulation). Tool chain priority: `slang --diag-json <file>` (JSON array of `{severity, message, code, optionName?, location: "f:l:c"}` — not installed on the host, fixture-tested only) → `verilator --lint-only -Wall -Wno-fatal` (with `--diagnostics-sarif-output` parsed as SARIF when `verilator --version` ≥ 5.038, classic `%Error[-CODE]: f:l:c: msg` text regex below) → iverilog `file.v:N: [error:] msg` → yosys `ERROR:`/`Warning:`. Normalization: dedupe identical diagnostics (` (×N)` suffix on the msg), msgs capped at 240 chars by cutting the MIDDLE (bit counts at the ends survive), ≤8 diagnostics (errors first, source order), caret snippets read back from the written .v file, `raw_stderr_tail` only when exit≠0 but nothing parsed. Tool versions are memoized per binary (`tool_version`).
- `tool_cache.py` — **Tool-result cache (Task 5)** for `write_and_check_syntax` and `run_simulation` only (synthesis is too stateful). Key: `sha256(tool_name + tool_version + verilog_code + testbench_code_or_empty)` where tool_name/version are the underlying EDA binary (e.g. `verilator` / its `--version` line). Storage: synchronous `sqlite3` at `backend/data/tool_cache.db` (override with `TOOL_CACHE_DB`; gitignored via `data/`) — deliberately not aiosqlite: the cache is touched from the sync lint fast path as well as the event loop, and short-lived per-call connections avoid the cross-loop/thread issues jobs.py manages. Cache hits append `"cached": true` to the lint JSON / a `(cached: true …)` line to the sim result; cached sim results have no `job_id` (no live job).
- `test_mock_backend.py` — Standalone mock WebSocket server (same protocol, fake tool-call frames) for frontend development without the real agent. Run with `python test_mock_backend.py`.
- `start.sh` — The one supported way to launch the backend: `exec .venv/bin/python -m uvicorn main:app --reload --timeout-graceful-shutdown 3 --host 0.0.0.0 --port 8000`. The `--timeout-graceful-shutdown 3` flag is mandatory: the frontend auto-reconnects its WebSocket every 2 s, which makes uvicorn's graceful shutdown hang forever on Ctrl+C, orphaning the reloader process (PPID 1) holding port 8000. If that happens: `pkill -9 -f "uvicorn main:app"`.
- Root-level `test_*.py` scripts (`test_ws.py`, `test_auth.py`, `test_agent_type.py`) are **manual probe scripts** (they run code at import time and need a live server/API key) and sit outside the pytest suite.

### Backend hardening services

- `project_repository.py` — Atomic per-project JSON repository. It serializes operations with per-project re-entrant locks and persists through same-directory temporary files, file fsync, `os.replace`, and directory fsync. Corrupt files are isolated instead of replacing in-memory state; chat saves, REST updates, and deletes share the same lock.
- `eda_workspace.py` — Trust boundary for all model-controlled EDA names and paths. It accepts only portable Verilog top identifiers, allow-lists supported SiliconCompiler targets, validates positive finite clock periods, and resolves every design/Fmax/artifact path beneath `SC_BUILDS` with symlink-aware containment checks. `sc_job.py` repeats validation at the subprocess boundary.
- Job lifecycle `status` is distinct from EDA `outcome`: completed runners use status `done` while outcome is `success | failure | inconclusive`; both SQLite and `job_status`/`GET /api/jobs` expose the outcome. The dashboard maps negative outcomes to failed/inconclusive chips.
- WebSocket delivery uses a 512-frame bounded outbox with reserved control capacity. Replayable stream frames may be discarded only with an `outbox_gap` marker; terminal/control frames are retained, and an all-critical overflow closes with code 1013. Session task admission is guarded atomically, so a rejected second prompt cannot replace the active cancellation handle.
- `genui.py` — Restricted interactive GenUI contract protocol and Phase 3 execution gate. A normal design request retains the original prompt, `define_architecture` creates a persisted `DesignSpec`-backed proposal, and the tool loop returns before RTL/EDA. Static app-owned components expose typed decision/revision actions; `contract.approve_and_build` locks the exact project/session revision and SHA-256 digest, then `main.py` resumes the saved request once through the normal serialized chat path. Material revisions revalidate and replace the executable `ArchitectureContract` and invalidate old checkpoints. No arbitrary HTML/CSS/JavaScript, runtime component definitions, or direct EDA/job action is reachable through GenUI. `contract_state` snapshots are broadcast live and replayed on project join.
- `evidence.py` / `evidence_api.py` — Versioned Pydantic `DesignSpec`, immutable terminal `RunManifest`, and derived `EvidenceReport` records exposed under `/api/evidence`. Canonical JSON is the source of truth; artifacts are stored by SHA-256 under `backend/data/evidence`; optional YAML uses safe loading/dumping. Run creation verifies the referenced spec hash/revision, parent lineage, and artifact references before deriving a conservative report.
- `golden_models.py` / `regression_corpus/` — Human-authored independent Python reference models for `alu8`, `counter8`, and `arbiter4`, deterministic directed-plus-seeded vectors, explicit reference-vs-DUT failure classification, atomic corpus persistence, and discovered-bug regression capture.
- `differential_regression.py` — JobManager-backed Verilator+cocotb execution of persisted golden vectors against generated RTL, with deterministic sampled events, explicit compile/runtime/reference/mismatch states, safe EDA workspaces, and optional Icarus portability smoke execution.
- `verification_executor.py` — Verilator SVA and structural-coverage execution plus cocotb-coverage 2.x functional bins/crosses over observed differential samples. It persists native, normalized, annotated, and LCOV artifacts when supported; unavailable tools remain inconclusive.
- `formal_toolchain.py` / `formal_executor.py` — Pinned-tool capability reporting plus SymbiYosys property proofs and EQY/native-Yosys RTL equivalence. Outcomes are `proven | failed | bounded | inconclusive`; empty obligation sets and missing tools never pass. Counterexamples and raw logs are durable artifacts.
- `gate_netlist.py` — **Canonical gate-netlist artifact (Phase G1, workbench plan)**: `gate-netlist/v1` built from the synthesis tool's structured Yosys JSON (`sc_job.emit_gate_netlist_json` runs `read_liberty -lib` + `hierarchy -top` WITHOUT `-check` so post-P&R power-pin connections do not abort; liberty files are found via manifest walk or `job0/*/0/inputs/*.lib`). Bounded `gate-graph/v1` views (`bounded_graph`) take module scope, depth 1..4, node limit 1..2000, and scope-local cone roots; Yosys emits integer attributes as ASCII bit-vectors, so black-box detection decodes them (`_truthy_attribute`) and liberty-loaded standard-cell modules are reported as black-box leaves; hierarchy expansion stops there. Persisted via the evidence store; durable per-job link in the jobs DB column `netlist_sha256`.
- `timing_paths.py` — **Ordered timing-path artifact (Phase G3)**: `timing-paths/v1` parsed from OpenSTA's ordered `setup/hold.topN.rpt` (incl. scenario corners): per-segment kind/name/delay/cumulative time, arrival/required/slack, corner, clock, analysis; segments mapped onto gate-graph ids with an explicit resolved/unresolved split and `partial` flag. Endpoint `GET /api/jobs/{id}/timing-paths?netlist_sha256=` rejects digest mismatches (409); DB column `timing_paths_sha256`.
- `physical_layout.py` — **Indexed layout view (Phase G4)**: `layout-view/v1` derived from the deepest routed DEF (`.def` or `.def.gz`, opened bounded): die area, rows, placed components with coordinates and netlist-mapped `graph_id`s (DEF bracket-escaping unescaped), IO pins (`+ DIRECTION` and legacy spellings), nominal cell footprint from the DEF's own row site/pitch (flagged nominal — LEF dimensions are never guessed), truncation/partial-mapping completeness. Endpoint `GET /api/jobs/{id}/layout?netlist_sha256=`; DB column `layout_view_sha256`. GDS is never parsed here.
- `cdc_rdc.py` — Conservative structural CDC/RDC analysis over Yosys JSON: domain discovery, two-flop synchronizers, unsafe crossings, reset-release checks, expiring scoped waivers, and explicit non-signoff limitations.
- `verification_pipeline.py` / `verification_api.py` — Ordered `lint → differential → assertions → functional coverage → structural coverage → formal properties → equivalence → CDC/RDC → portability` orchestration, requirement matrix, evidence persistence, and conservative synthesis/delivery gate. Formal, equivalence, and CDC/RDC become mandatory from explicit DesignSpec controls (CDC/RDC is also inferred mandatory for multiple declared domains). The agent tool is `run_verification`; REST endpoints live under `/api/verification`.
- `verification_policy.py` — Project-owned stable lint rule IDs and severities, scoped expiring waivers, typed assertion and functional-coverage requirements derived from `DesignSpec`, bindable SVA checker generation, per-design-class thresholds, and machine-readable verification gate evidence. `lint.py` and `write_and_check_syntax` accept this policy additively without changing legacy output when no policy is supplied.

## Field fixes applied (documented so they survive refactors)

Two SiliconCompiler 0.38 / OpenROAD 26Q2 incompatibilities blocked the end-to-end pipeline on this machine:

1. **Utilization sentinel crash** — OpenROAD 26Q2 reports `utilization: -1` for post-synthesis steps with no die area; SC's metric recorder then fails schema validation (`-100.0 not in range 0.0..`) and kills the whole run at `cleanup.clean/0`. Fixed by a local patch to `backend/.venv/.../siliconcompiler/tools/openroad/_apr.py` (skip negative utilization). Re-apply after any venv rebuild.
2. **Broken freepdk45 flowgraph** — `freepdk45_demo` removes `route.repair_timing/0` (post-route timing repair disabled) but `route.antenna_repair/0` still requires its outputs (`<top>.sdc`, `<top>.odb.gz`), so the run aborts at flowgraph validation with "Flowgraph file IO constrains errors". Worked around by defaulting to `skywater130_demo` (see `eda_tools.run_silicon_compiler`).
3. **Docker volume permission (lambdapdk download)** — the compose named volume `sc_cache` mounts at `/home/agent/.sc`; if the image lacks that directory, Docker creates the mount point **root-owned** and the `agent` user cannot download the sky130 PDK, so every SC node fails its required-file check with the opaque "Tools requirements not met". Fixed in the `Dockerfile` by pre-creating `/home/agent/.sc` owned by `agent` (named volumes inherit image ownership on first creation). An already-created broken volume needs a one-time `docker compose exec -u root backend chown -R agent:agent /home/agent/.sc`. Also note: `docker compose restart` never re-reads `.env` — after changing `KIMI_API_KEY` use `docker compose up -d` (recreates the container).

## Security and Environment Considerations

- `KIMI_API_KEY` must be available to the backend process — exported in the same shell that runs uvicorn, or in `backend/.env` (loaded at startup via python-dotenv, gitignored). Never commit it. `MISTRAL_API_KEY` is **optional** and needed for the `mistral-vibe` and `mistral-glm-5.3` entries — obtain it via the setup wizard (`python mistral_setup.py` or the web UI's *mistral setup* button) or paste it into `backend/.env` by hand; without it the Mistral entries show as unavailable, exactly like `OPENROUTER_API_KEY`. `frontend/.env` holds frontend env vars and is gitignored — do not read or print it. `OPENROUTER_API_KEY` is **optional** and only needed for the `openrouter-*` entries in `model_registry.py`; without it those models simply show as unavailable (`available: false` in `GET /api/models`) and selecting one yields a clear error frame in chat.
- Backend CORS allows all origins and the server binds to `0.0.0.0` — this is a **local-dev-only** configuration; do not deploy as-is.
- **Single-user by design (decided 2026-09-19):** the whole stack is single-tenant — one backend instance per machine, no user concept in sessions/projects (anyone reaching port 8000 sees every project), one shared job registry and build tree. The Docker image is built once and run as one long-lived container per machine, replacing the host venv + host EDA installs. **Multi-user is explicitly deferred**: productizing would require auth on `/ws`, per-user project/job namespaces, per-user build roots, and a worker queue (arq or SC's remote server) — a large redesign that goes well beyond a config change. Don't paper over it with "one container per user" either; that's an orchestration project of its own.
- The EDA tools write to and depend on `/mnt/cold-hdd` via `SCPATH`/`SC_BUILDS` in `backend/.env`; synthesis will fail on machines without that mount (or change the env vars to point elsewhere).
- EDA tool setup on this machine (Debian 13 — `sc-install` only supports Ubuntu/RHEL): `yosys`/`verilator`/`iverilog`/`sby`/`z3` live in the project-local, gitignored prefix `.tools/eda/bin` (rebuild with `scripts/install-local-eda.sh` and `scripts/install-local-formal.sh`; the Tcl runtime with `scripts/install-local-timing-runtime.sh` — its `lib/` must be on `LD_LIBRARY_PATH` or yosys cannot find `libtcl8.6.so`); **OpenSTA built from source** at `/mnt/cold-hdd/OpenSTA/build/sta` (needs CUDD, built at `/mnt/cold-hdd/cudd/install` and passed to cmake via `-DCUDD_DIR=`); `/mnt/cold-hdd/OpenSTA/build` is added to `PATH` in `~/.bashrc`. **OpenROAD installed via Nix** (`nixpkgs#openroad`, 26Q2, at `~/.nix-profile/bin`, on PATH via `~/.bashrc`). **KLayout installed via Nix** (`nixpkgs#klayout` 0.30.12, same profile; install with `scripts/install-klayout.sh`) — required for `flow_mode="pnr"` (SC fails closed without yosys+openroad+klayout) and with it the Phase G4 layout view. Tools must be on the PATH of the shell that starts uvicorn; detection is per-call via `shutil.which`. Beware: shells spawned by some editors carry a `LD_LIBRARY_PATH` pointing at the editor's bundled `libstdc++`, which breaks `iverilog`/`yosys` subprocesses — unset it or set it to `.tools/eda/lib`.
- **Local patch**: `siliconcompiler/tools/openroad/_apr.py` in `backend/.venv` is patched to skip negative `utilization` metrics (OpenROAD 26Q2 reports a -1 sentinel post-synthesis; SC 0.38 otherwise crashes recording it). Re-apply if the venv is rebuilt; remove when siliconcompiler is upgraded past the fix.
- The `/ws` endpoint is unauthenticated.
